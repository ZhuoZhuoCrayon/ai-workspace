# 自定义指标存储选型与压测报告

**选型：D 元信息建表，即定义表、例外取值表与上报范围、范围标签、上报成员三张新表，已有表零 DDL。** 在 MySQL `5.7.44` 上对四个完整方案端到端压测，只有 D 同时满足四项功能且迁移失败时存量功能不受影响。B 按服务拆行的最大数据源管理页首页 `28.6 s`、上界规模新增 `42.1 GiB`，C 元信息加列读写与 D 同量级，但加 `5` 列整表重建 `68.4 s`，迁移失败时 `5` 项存量功能中 `4` 项报 `1054`。

`9.2` 上的单项结论在 `5.7` 上大多成立，改变的有两处：同一画像下服务视图不再区分展开与窄成员表，定义表逐行关联时整组读取与全平台扫描比扩列慢 `60%`、`76%`，原生 arm64 构建上为 `49%`、`38%`。按范围不同的取值，定义行让「指标默认值」从对成员计票的 `709 ms～940 ms` 降到 `66 ms`，例外引用按指纹去重的取值，体积不随例外比例与全体改值膨胀。

压测数据按平台 `1,000,000` 个指标项全量构造，画像取自上云环境（bkte）的抽样。完整方案对比在 Docker 的 MySQL `5.7.44`（amd64 模拟）上运行，单项选型压测在本机 MySQL `9.2.0` 上运行，两者缓冲池都容纳全部热数据，结论看相对差。版本兼容在 MySQL `5.7.44`、`8.0.46` 上验证。

## 0x01 结论

| 问题 | 结论 | 依据 |
| --- | --- | --- |
| 完整方案 | D 元信息建表 | `5.7` 上四项功能全部满足，已有表零 DDL，迁移失败时存量功能 `0/5` 报错 |
| 服务是否进入指标项身份 | 否 | `5.7` 上最大数据源管理页首页 `28.6 s`，上界规模新增 `42.1 GiB`，`9.2` 上首页 `1,133 ms` |
| 是否分表 | 否 | 分 `16` 张表后最大数据源管理页首页 `1,387 ms`，热点数据源整组落在一张分表 |
| 上报关系存储 | 窄成员表 | 上界规模成员 `6,749 MiB`，`5.7` 上展开方案的最大数据源管理页首页慢 `530` 倍 |
| 元信息落点 | 独立定义表 | [a] 已有表零 DDL，迁移失败不影响存量功能<br />[b] `5.7` 上整组读取与全平台扫描比扩列慢 `38%～76%` |
| 按范围不同的取值 | 定义加例外引用 | 指标默认值 `66 ms`，对成员计票的存法 `709 ms～940 ms`，上界规模体积 `5.8 GiB～6.2 GiB` |
| 成员回收 | 唯一键分段扫描，不建 `last_seen` 索引 | 最大数据源单组 `2.75 s`，上界规模省 `1,123 MiB` |
| 写入 SQL | 先查后插，必须 upsert 时用 `VALUES()` | [a] `5.7` 不支持行别名<br />[b] upsert 每批消耗与批大小相同的自增 ID |
| 索引文本列字符集 | `utf8` | `utf8mb4` 的 `varchar(255)` 在 COMPACT 行格式下报 `1071` |
| `__scope` 表示 | 哈希唯一键加标签倒排 | `1,000` 个服务时按服务过滤 p50 `0.070 ms` |
| 主键形态 | Django 自增主键加唯一键 | 成员表比复合主键大 `14.6%` |

## 0x02 完整方案对比（MySQL 5.7）

四个完整方案在 MySQL `5.7.44` 上用同一份数据跑同一组用例，D 是唯一同时满足四项功能、已有表零 DDL、迁移失败时存量功能不受影响的方案。B 的最大数据源管理页首页 `28.6 s`、上界规模新增 `42.1 GiB`，在 `5.7` 上比 `9.2` 更不可行。C 的读写与 D 同量级，但加 `5` 列要整表重建，迁移失败时 `5` 项存量功能中 `4` 项报 `1054`。C、D 的关系表装满上界规模 `4,009` 万行后，读写耗时与 `232` 万行时相差在 `11%` 以内。

执行计划的差异集中在三处，只有 `OFFSET 10000` 的改道同时影响 A、C、D，不改变方案间的排序：

- B 的管理页按指标名分组时带 `tag_list`（LONGTEXT）与 JSON 列，`5.7` 的内部临时表遇到 TEXT 与 BLOB 列直接落盘，去掉这两列后单次分页从 `19.5 s` 降到 `4.8 s`。
- `OFFSET 10000` 在 `5.7` 上改走 `idx_group_scope_field` 加 filesort，排序 `10,050` 行，`9.2` 沿唯一键顺序读取，现状从 `36.1 ms` 变为 `183 ms`。
- D 的整组读取与全平台扫描对每个指标项做一次 `uk_group_name` 的 `eq_ref`，`5.7` 上相对现状的增量分别是扩列的 `3.4` 倍与 `3.8` 倍。
