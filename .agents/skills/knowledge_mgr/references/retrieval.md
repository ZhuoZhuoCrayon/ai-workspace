# Retrieval Guide

只在检索场景阅读本文件，纯写操作不要预加载本文件。

## 0x01 适用场景

当任务属于以下任一类时，读取本文件：

- 回答依赖历史知识资产的项目问题
- 继续某个知识对象目录的既有上下文
- 编码前核对既有方案、排障结论或代码片段
- 核对 public / private 知识是否一致
- 为写操作补齐前置证据

## 0x02 检索契约

### a. 输入前提

输入上下文至少包含：
* 项目名：明确指定或从上下文中推断出当前项目，例如 Git URL、项目相关文档路径、issue 目录路径等。
* 当前任务目标： 
    * 明确当前任务的目标是什么，例如“回答项目问题”、“继续既有 issue”、“核对方案”、“核对知识一致性”或“补齐前置证据”等。
    * 识别意图并猜测搜索关键字，用于后续检索。

### b. 检索优先级

回答项目问题、执行项目任务或出现知识目录检索行为时，按以下优先级检索并采信：

1. 会话上下文
2. 项目知识库：`knowledge/<project>/`
3. 项目自身规范：`<local_path>`（如 `CONTRIBUTING.md`、`README.md`、`AGENTS.md` 等）
4. 项目源码：`<local_path>`
5. 通用知识：`knowledge/_shared/`
6. 工作区全局指导：`AGENTS.md`

### c. 约束

- 输出证据至少包含：`路径`、`命中理由`、`updated` 或最近更新时间。
- **【CRITICAL（必须执行不可协商）】** 知识库默认并行检查 `knowledge/` 与 `private/knowledge/` 两侧，禁止只读取任一侧后直接下结论。
- 命中 `snippet` 时，默认直接给出与当前任务最相关的代码块、命令块或关键片段，并解释其用途、输入参数和执行效果，不要只返回路径。
- 命中 `troubleshooting` 时，默认直接给出“现象 → 根因 → 排查过程 → 解决方案 / 注意事项”，路径与更新时间作为辅助证据放在后面。
