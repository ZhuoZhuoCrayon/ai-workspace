# 文本

## 0x01 句子原则

- **【硬约束】长句必须中心思想先行**：先判断信息关系并选择载体，再改写为「主句：细节」或「概要句 + 分点」。
- 出现「条件 + 动作」「背景 + 结论 + 细节」「A，且 B」等串联结构时，按 `paragraph.md` 的载体选择规则处理。
- 同一段落或列表项内不堆叠多个长句：每句只表达一个信息点。
- 句式偏好简单句和并列句：避免复合句和定语从句嵌套。
- 优先用肯定句：避免双重否定（"没有 X 就不能 Y" 改写为"必须 X 才能 Y"）。
- 行宽以渲染文本为准：渲染不超过 `120` 字符时写成一行，超链接 URL 和 Markdown 标记不计入，不为源码行宽硬拆句。
- 源码换行不等于渲染结构：禁止为了通过检查只做硬换行或连续孤立短段。
- 删除空泛词与口语化表达：避免“进一步优化”“增强体验”“简单来说”“这里先说明一下”这类内容。

## 0x02 写作风格

- 优先主动语态：少用被动语态。
- 用现代汉语常用表达：不用冷僻、生造或文言文词语。
- 区分「的 / 地 / 得」：形容词 + 的 + 名词、副词 + 地 + 动词、动词 + 得 + 副词。
- 代词指代必须明确：使用「其」「该」「此」「这」时确保只有一个含义。
- 名词前不堆叠多层形容词：把修饰语拆成独立短句承载。

## 0x03 字间距

- 中文与英文之间加空格：例如"启动 Windows 系统"。
- 中文与阿拉伯数字之间空格可选：但全文风格必须统一。
- 数字与英文单位之间留空格：例如 `16 GB`、`60 min`。
- 英文字符或阿拉伯数字接全角标点时不加空格：例如 `MacBook Air，` 中间不空格。

## 0x04 英文处理

- 英文复数翻译为中文时还原为单数：如 RAMs 译为 RAM。
- 中文语境下英文省略号 `...` 改为中文 `⋯⋯`。
- 中文语境下英文书名或电影名改用书名号 `《》`：替代英文双引号。
- 首次出现英文术语时给中文标注：后续可直接用缩写（如 IOC、API）。
- 专有名词每个单词首字母大写：非专有名词不大写。

## 0x05 链接与微观格式

| 主题   | 规则                                                      |
|------|---------------------------------------------------------|
| 链接文案 | 使用摘要文案，不用裸 URL                                          |
| 路径引用 | 引用工作区文件用完整相对路径，例如 `knowledge/<project>/snippets/xxx.md` |
| 引用外部 | 引用外部资料时给出来源或链接                                          |
| 代码标识 | 标识符用反引号包裹，代码块标注语言类型                                     |
| 源码链接 | 使用 Markdown 链接格式：`[<源码> <项目名>/<文件路径>](<GitURL>)`              |

## 0x06 正反案例

### a. 源码换行不能替代结构

Bad：

```md
先读取配置文件。
再执行文档检查。
最后同步 skill。
```

Good：

```md
执行顺序：

1. 读取配置文件。
2. 执行文档检查。
3. 同步 skill。
```

### b. 不因链接源码长度拆散自然句

Bad：

```md
Use **reStructuredText (rst)** docstrings because Sphinx `autodoc` parses rst fields.

Reference: [reStructuredText (rst)](https://www.sphinx-doc.org/en/master/usage/restructuredtext/index.html).
```

Good：

```md
Use [**reStructuredText (rst)** style](https://www.sphinx-doc.org/en/master/usage/restructuredtext/index.html) because Sphinx `autodoc` parses rst fields.
```
