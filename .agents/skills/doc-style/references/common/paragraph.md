# 段落与载体

## 0x01 段落原则

每段回答一个问题，保留会改变读者判断或操作的条件。

| 读者要判断什么 | Bad | Good |
| --- | --- | --- |
| 一项迁移失败，调度程序会看到什么？ | 记录失败项，支持重跑。 | 回滚失败项后继续处理其余项，整批结束时只要有失败就返回非零退出码。 |
| 侧栏打开后还能看到事件列表吗？ | 声称背景列表仍可见，只配侧栏内的缩放截图。 | 用包含背景列表的全图说明侧栏布局，用局部图说明缩放动作。 |

## 0x02 载体选择

同一信息选一个主要载体，按读者要做的事来选。

| 阅读任务 | 适合的写法 |
| --- | --- |
| 理解决定或因果 | 简短段落，交代判断及理由 |
| 顺序执行或逐项核对 | 有序步骤或短列表 |
| 比较多个对象 | 表格，只保留有比较价值的列 |
| 追踪分支、归属或协作关系 | 用图展示难以用文字看清的关系，关键算法可用伪代码 |
| 复现接口或配置 | 用最小示例展示写法，字段约束按需查表 |

表格同列使用相同信息类别，路径和标识符用反引号标出。短枚举用顿号，需逐项对照的内容用 `<br />` 分行。重复值可上提到表前。

**就近注脚**

正文写论断和行动所需的限制。在论断处标注引用，把支撑它的源码链接和必要补充写成紧随段落或图表的独立注脚，读者可按需核验。

```markdown
| 规则类型 | 数据特征 | 唯一语义 |
| --- | --- | --- |
| 全局规则 | `<is_global=true, service_names=[]>` | `kind + code` |
| 服务规则 | `<is_global=false, service_names=[svc-a, svc-b, ...]>` *[1]* | `kind + code + remark` *[2]* |

- *[1] [读取规则的实现](相应源码链接)在查询时补齐内置备注，存储中仅有用户覆盖项。*
- *[2] `service_names` 只表达这条规则的作用范围，不参与规则身份判定。*
```

代码和 Mermaid 源码不插入注脚标记，注脚直接写明对应的标识符或节点。

## 0x03 协议类文档

以实现或查询协议为目的时，读者应能复原所需结构。展示嵌套关系或调用方式用最小可用示例。查询类型、必填性或取值约束用字段表，写清字段路径，复杂子结构可分表。

裁剪示例时保留完成该动作所需的上下文、层级和输入关系，使读者替换自己的值即可使用。示例之外只解释影响用法的默认值、例外或兼容条件。
