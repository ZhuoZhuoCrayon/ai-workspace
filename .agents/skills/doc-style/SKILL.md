# Doc Style

## 0x01 定位

`doc-style` 负责 Markdown / MDC 文档的结构设计、表达压缩与交付前润色。

适用范围：

- 文件范围：所有 `.md` / `.mdc` 文档编辑、重构、润色与验收。
- 其他文档类型：规则文档、普通说明文档。
- 短交付：PR review 评论、GitHub 评论、零散草稿的结构化压缩。

职责边界：

- 只处理文档内容、结构和表达。
- 不负责外部资产定位、元数据治理或发布流程。

## 0x02 通用必读

【CRITICAL（必须执行，不可协商）】无论文档类型是什么，都必须先读 `references/common/` 下全部 `5` 个文件：

- [Title](references/common/title.md)
- [Text](references/common/text.md)
- [Paragraph](references/common/paragraph.md)
- [Number](references/common/number.md)
- [Marks](references/common/marks.md)

## 0x03 第一性原理

文档的价值是帮助读者快速找到核心信息，准确理解内容并完成文档所支持的判断或行动。所有 Markdown / MDC 文档交付前都必须做一次编辑压缩：先检查重点与信息取舍，再检查措辞和格式。

1. **信息围绕读者需求取舍**：每项内容既要有信息增量，也要服务文档目的，删除不影响理解、判断或使用的材料。
2. **主线使用合适的载体**：按信息关系选择段落、列表、图表或示例，同一信息只保留一个主要载体，避免结构与文字互相复述。
3. **正文与注脚分工**：正文保留核心信息、必要理由和影响理解或行动的限制，来源依据、局部例外及补充说明放入就近注脚，不得通过搬入注脚保留冗余。
4. **职责必须可定位**：句子应能识别谁在什么条件下对什么对象执行什么动作，不把多个角色或层级的职责写在一起。
5. **过程按用途保留**：稳定文档描述当前事实和目标契约，调查、推导或历史过程仅在文档目的需要时保留，不把作者的工作记录直接当成交付正文。

## 0x04 写作流程

1. **判定目标**：明确目标读者、交付形态，以及读者需要理解、查找或完成什么，不套用固定场景的章节模板。
2. **读取规范**：完整阅读 `common/` 全部 `5` 个文件。
3. **取舍信息**：按读者需求区分主线、必要补充和可删除材料，合并重复结论与相同规则。
4. **选择载体**：按信息关系组织主线，依照 `paragraph.md` 安排图表和就近注脚。
5. **完成初稿**：句子使用明确主语，不混写职责，区分当前事实、目标要求和历史记录。
6. **编辑压缩与自检**：按 `0x05` 从整体到局部检查，保留必要信息，不以字数或固定删减比例代替质量判断。

## 0x05 润色与自检

### a. 润色

1. **读取规范**：完整阅读 `0x02` 提及的全部文档和 [Humanizer](references/humanizer.md)。
2. **编辑压缩**：检查读者能否快速找到核心信息，按 `0x03` 调整主次、合并重复并删除无关内容，正文与注脚一起审查。
3. **逐句检查**：识别空泛引导、历史语气、模糊主语、职责混写和抽象结论。
4. **重写违例**：保留原意和必要上下文，用明确的主体、动作、对象和条件重写。
5. **呈现版本**：交付修订后的完整版本，不只列问题清单。

修订后的文本必须满足：

- 大声朗读时听起来自然
- 自然地改变句子结构
- 使用具体主体、动作、对象和条件，不用模糊主张
- 为上下文保持适当的语气
- 适当时使用简单的结构（是/有）

### b. 输出闸门

【CRITICAL（必须执行，不可协商）】审稿自检不能用自动检查替代，低于 `90` 分时，回到 `0x05.a` 重新润色。

| 维度 | 评估标准 | 得分 |
| --- | --- | --- |
| **重点与直接性** | 是否围绕文档目的突出核心信息，让读者快速定位所需内容，删除空泛引导 | /8 |
| **具体性** | 是否写清主体、动作、对象、条件和结果，避免“相关处理”“进一步优化”等模糊表达 | /8 |
| **职责边界** | 每项职责是否归属明确，同一句或同一列表项是否混入多个角色或层级 | /8 |
| **结构承载** | 载体是否匹配信息关系，正文与就近注脚是否分工清楚，重要限制是否保留在主线 | /8 |
| **时间稳定性** | 是否按文档用途区分当前事实、目标与历史，避免将调查过程误作稳定规则 | /8 |
| **清晰度** | 是否存在黑话、术语堆叠、被动嵌套、长定语或不明确指代 | /8 |
| **精炼度** | 是否合并重复、删除无关过程和细节，注脚是否仍有冗余，压缩是否保留必要信息 | /8 |
| **自然度** | 句式和节奏是否自然，是否避免机械排比、公式结构和过度解释 | /8 |
| **文档审美** | 结构、信息层级、行文节奏、留白和对齐是否支持快速阅读 | /8 |
| **common 规范** | 按 `0x02` 的 `5` 个 common 文件检查。不满足一点扣 `2` 分，扣分上限为 `28` 分 | /28 |
