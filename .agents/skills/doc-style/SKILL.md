# Doc Style

## 0x01 定位

`doc-style` 负责 Markdown / MDC 文档的结构设计、表达压缩与交付前润色。

适用范围：

- 文件范围：所有 `.md` / `.mdc` 文档编辑、重构、润色与验收。
- 其他文档类型：规则文档、普通说明文档。
- 短交付：PR review 评论、GitHub 评论、零散草稿的结构化压缩。

职责边界：

- 只处理文档内容、结构和表达。
- 不负责外部资产定位、元数据治理或发布流程。

## 0x02 通用必读

【CRITICAL（必须执行，不可协商）】无论文档类型是什么，都必须先读 `references/common/` 下全部 `5` 个文件：

- [Title](references/common/title.md)
- [Text](references/common/text.md)
- [Paragraph](references/common/paragraph.md)
- [Number](references/common/number.md)
- [Marks](references/common/marks.md)

## 0x03 写作流程

1. **判定目标**：明确文档目标读者、交付形态和读者需要拿到的结论。
2. **读取规范**：先读 `common/` 全部 `5` 个文件。
3. **完成初稿**：按规范写作。
4. **润色与自检**：见 `0x04`。

## 0x04 润色与自检

### a. 润色

1. **读取规范**：完整阅读 `0x02` 提及的全部文档和 [Humanizer](references/humanizer.md)，作为润色规范
2. **细读文本**：仔细阅读待润色文本，标出不符合润色规范的实例
3. **重写违例**：就地重写问题片段，保留原意和目标读者需要的上下文
4. **呈现版本**：交付人性化版本，不只列问题清单

修订后的文本必须满足：

- 大声朗读时听起来自然
- 自然地改变句子结构
- 使用具体细节而不是模糊的主张
- 为上下文保持适当的语气
- 适当时使用简单的结构（是/有）

### b. 输出闸门

【CRITICAL（必须执行，不可协商）】审稿自检不能用自动检查替代，低于 `90` 分时，回到 `0x04.a` 重新润色。

| 维度 | 评估标准 | 得分 |
| --- | --- | --- |
| **直接性** | 直接陈述事实还是绕圈宣告？<br />`8` 分：直截了当<br />`1` 分：充满铺垫 | /8 |
| **节奏** | 句子长度是否变化？<br />`8` 分：长短交错<br />`1` 分：机械重复 | /8 |
| **信任度** | 是否尊重读者智慧？<br />`8` 分：简洁明了<br />`1` 分：过度解释 | /8 |
| **真实性** | 听起来像真人说话吗？<br />`8` 分：自然流畅<br />`1` 分：机械生硬 | /8 |
| **精炼度** | 还有可删减的内容吗？<br />`8` 分：无冗余<br />`1` 分：大量废话 | /8 |
| **黑话清单** | 仅在特定圈层成立、脱离圈层即丢失语义的词语。圈外读者无法独立读懂，依赖默会知识、内部缩写、外文夹杂或隐喻 | /8 |
| **晦涩清单** | 读完仍需回看才能理解的语句。常见问题包括术语堆叠、被动嵌套、省略主语、长定语前置 | /8 |
| **冗余清单** | 对结论无新增信息量的内容。常见问题包括过程叙述、跨节重述、为衔接而衔接的句子 | /8 |
| **审美缺点清单** | 以「极高文档审美的专业领域评审专家」视角检查结构、行文、叙事节奏、信息层级、留白与对齐 | /8 |
| **common 规范** | 按 `0x02` 的 `5` 个 common 文件检查。不满足一点扣 `2` 分，扣分上限为 `28` 分 | /28 |
