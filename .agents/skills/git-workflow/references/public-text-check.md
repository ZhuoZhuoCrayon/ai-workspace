# 公开文本敏感信息检查

公开 PR / MR 的创建、标题与正文更新，以及 review 草稿、行内评论、汇总评论和审批正文，均检查本次确切发布的文本。
补充技术说明或修正文案后重新扫描，不复用旧文本的结果。

## 0x01 发布顺序

1. 确认目标仓库的可见性，并将标题、正文及各条评论保存为独立 UTF-8 文件。
2. 从本 Skill 的实际目录执行扫描，`--project-root` 指向已配置 PreCI 的目标仓库。
3. 仅当报告为 `passed` 且退出码为 `0` 时，使用同一批文件提交发布请求。
4. 发布后回读标题、正文和评论，逐项比对已扫描内容；意外追加的内容同样先检查再修正。

```bash
python3 <git-workflow-skill-dir>/scripts/check_public_text.py \
  --project-root <target-repo-root> \
  /tmp/pr-title.txt /tmp/pr-body.md /tmp/review-body.md
```

文件应只包含准备公开的内容，不把内网 TAPD 正文、用户截图、运行日志或凭据加入扫描输入后直接发布。
公开侧用 `--story=<shortID>` / `--bug=<shortID>` 关联单据，内网链接与业务证据保留在内部单据。

## 0x02 结果判读

| 退出码 | 含义 | 动作 |
| --- | --- | --- |
| `0` | 本地规则与 PreCI 均通过，报告含文本 SHA-256 | 发布相同内容 |
| `1` | 本地发现内网域名、私网 IPv4 或疑似凭据 | 脱敏后重新扫描 |
| `2` | 文件无效、PreCI 不可用／未通过，或扫描时文件变化 | 排除原因后重新扫描 |

脚本只输出文件、行号与规则名，不回显命中内容或 PreCI 原始输出。
缺少 PreCI、未配置、超时、仅返回 `0` 或出现跳过提示，都不能记为已完成敏感信息检查。

## 0x03 已验证的边界

`preci scan --projectPath <repo-root> <file>` 支持指定单个文本文件，不需要将草稿暂存或提交。
`--pre-commit` 扫描 Git 暂存区，不能替代 PR / review 文本检查。

本机 `2025.10.24-prod2.24` 的 CLI 实测接受 `.md`、`.txt` 和 `.py` 文件，但内网域名样例仍返回无缺陷。
本地规则补充内网域名、编码后的域名、RFC1918 IPv4 与常见凭据形态；PreCI 继续执行项目配置的扫描能力。
两者均未命中仍需人工核对公开范围，不能将扫描通过解释为覆盖所有敏感信息。

## 0x04 CLI 自动生成内容

GTM 或其他 CLI 会从单据标题、提交说明、模板和配置生成公开内容。
创建 PR 前检查这些来源对应的最终标题、正文与默认评论；不能因 CLI 随后会创建空正文而跳过标题检查。
更新 PR 或评论时同样重新检查最终文本，禁止先发布再扫描，也不能在扫描后追加内网链接。
